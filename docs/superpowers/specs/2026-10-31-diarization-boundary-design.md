# Диаризация и отдельный навык назначения имён

Статус: дизайн просмотрен пользователем; уточнение от 2026-10-31 включено. Реализация разрешена командой «продолжай».

## Решение пользователя

Два независимо устанавливаемых компонента в одном репозитории, связанные файлом транскрипции:

- `whisper`: официальный Whisper распознаёт речь, pyannote разделяет её по говорящим. Сервис сохраняет текст, время и условные идентификаторы участников.
- Автономный навык `skills/name-speakers`: по команде пользователя читает готовый файл и назначает имена с учётом переписки и доступного контекста проекта. Навык не запускает распознавание и не требует установленного Whisper, pyannote или MCP.

Список участников, поиск имён и догадки о личности не входят в API сервиса. «Только разделение на участников» сохраняет существующее распознавание текста и исключает назначение имён.

## Рассмотренные подходы

1. Назначать имена внутри сервиса распознавания: связывает обработку аудио с контекстом агента и уточнением имён.
2. Разделить распознавание с диаризацией и последующее назначение имён, передавая результат через файл: выбран пользователем; компоненты имеют независимую установку и связаны только данными.

WhisperX для этого разделения не требуется. Сохраняются официальный Whisper `small`, начальный язык `ru`, CUDA без перехода на CPU и одноразовый Docker-контейнер.

## Предлагаемый контракт файла

При включённой диаризации сервис дополнительно сохраняет `transcript.diarized.json`. Существующий `transcript.json` Whisper сохраняет свой формат. Текстовые и субтитровые форматы остаются вариантами представления результата; межпроектный контракт — JSON.

Минимальные поля нового файла:

- `schema_version`: `1`.
- `source`: относительный путь исходного медиа.
- `language`: язык распознавания.
- `speakers`: список условных идентификаторов `Speaker1`, `Speaker2` и далее.
- `turns`: исходные интервалы диаризации с `start`, `end`, `speaker_id`; допускают одновременную речь.
- `segments`: реплики с уникальным в файле `id`, `start`, `end`, `text`, `speaker_id` и временными метками слов для сопоставления с диаризацией.

`speaker_id` относится только к данной записи и не обещает узнавания человека на другой встрече или при повторном распознавании. Если говорящего надёжно назначить нельзя, используется `null`; неизвестное имя известного голоса сохраняется как `SpeakerN`.

Реплики разделяются при смене назначенного говорящего. Исходные перекрывающиеся интервалы сохраняются отдельно; единичная метка реплики не означает, что сервис разделил одновременно звучащие голоса на отдельные аудиодорожки.

## Сервис whisper

Предложение: добавить явный параметр `diarize`, по умолчанию `false`, в CLI/MCP и общий обработчик. Это сохраняет существующий сценарий распознавания. При включении параметра новый JSON входит в предварительную проверку коллизий и список выходных файлов независимо от выбранного формата представления.

Имена участников и контекст проекта сервису не передаются. MCP и журнал возвращают только пути и служебные метаданные; текст остаётся в файлах. При ошибке диаризации запрос не объявляется успешно завершённым с диаризацией.

Веса pyannote кэшируются между контейнерами. Токен загрузки не включается в образ, результаты или журнал. Совместимость зависимостей, работа CUDA и потребление памяти требуют проверки в обычной Windows/WSL-сессии.

## Отдельный навык

Навык получает путь к файлу и действует по запросу пользователя. Имена из чата и контекста проекта — кандидаты для сопоставления, а не доказательство личности говорящего. Список присутствовавших не задаёт точное число прозвучавших голосов.

Предлагаемое поведение:

- Сохранять исходные `speaker_id` и идентификаторы реплик.
- Различать предположение об имени и подтверждение пользователя; фиксировать источник и основание назначения.
- При недостатке оснований оставлять `SpeakerN`, не распределять оставшиеся имена автоматически.
- Принимать как глобальные соответствия (`Speaker2 — Алексей`), так и поправки отдельных реплик, если диаризация ошиблась.
- Сохранять исправленную копию с таблицей соответствий и сведениями об исправлениях; перезаписывать существующие файлы только по явному разрешению.

Навык не строит базу голосов и не узнаёт людей по эталонным аудиозаписям. Предположения делает агент, работающий с текстом и контекстом; отдельный API модели для этого не нужен.

Навык хранится в `skills/name-speakers` этого репозитория и работает с любым доступным агенту файлом транскрипции с метками говорящих, включая JSON, TXT, Markdown, SRT и VTT. Он не требует собственного JSON-формата whisper. При неизвестной структуре агент сначала выясняет расположение меток и не выполняет слепую замену по всему документу.

Полный установщик предлагает установку навыка в проект, в общие навыки выбранного агента либо пропуск. Самостоятельная установка копирует только каталог навыка: без npm-зависимостей, Docker и моделей. Для автоматического запуска предусмотрены явные параметры назначения. Каталог конкретного агента задаёт пользователь; общий переносимый вариант — `.agents/skills` в проекте или в домашнем каталоге. Существующий навык не перезаписывается молча.

## Проверка и порядок работ

После согласования дизайна: реализовать диаризацию и контракт в whisper, создать автономный навык и независимый установщик, затем подключить его к полному установщику. Проверить границы формата, отсутствие текста в MCP/журнале, защиту от перезаписи и сообщения об ошибках. Для навыка проверить неоднозначные имена и исправления на синтетическом файле.

Реальная сборка Docker, CUDA и качество диаризации на русской записи проверяются отдельно вне песочницы; локальные модульные тесты не заменяют эти проверки.
