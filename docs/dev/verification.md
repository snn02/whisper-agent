# Состояние проверок

Актуально для изменений в `main` после локальной версии 1.1.0, 31 октября 2026 года. Это сведения о выполненных проверках, а не обещание качества на любой записи.

## Текущий результат

С диаризацией сервис создаёт один TXT с отметками времени и объединяет последовательные фрагменты одного определённого голоса. Неизвестные фрагменты остаются отдельными. SRT/JSON/all с диаризацией отклоняются до обработки; обычные форматы Whisper доступны без диаризации. Имена назначает отдельный переносимый навык.

## Автоматические проверки

Из корня репозитория:

```bash
npm test
python3 -m unittest discover -s tests -p 'test_*.py' -q
python3 -m compileall -q container
git diff --check
```

Node: 20 тестов. Python: 22 теста, из них проверка настоящего SRT-форматтера пропускается, если Whisper отсутствует в окружении. Она отдельно проверена в Docker с установленным Whisper; модульные тесты не требуют загрузки моделей.

Проверяются объединение реплик, смена участников, отдельные неизвестные фрагменты, отметки времени после часа, пустая запись, оригинальный SRT, выбор формата до запуска Docker, защита путей и перезаписи, ошибки файлов, журнал метаданных, MCP и автономная установка навыка.

## Windows, CUDA и MCP

Полная сборка стека и установка сервиса ранее проверены на Windows с NVIDIA GeForce RTX 5060 Laptop GPU: CUDA, Whisper small/ru, pyannote и доступ к весам через HF_TOKEN. После изменения формата установленный runtime обновлён; рабочий образ обновлён поверх уже проверенного окружения с заменой Python-обработчика. Это не новая сборка зависимостей с нуля.

Текущий воспроизводимый сценарий находится в `tests/windows`. Он использует уже установленный runtime и рабочий образ, создаёт временную русскую запись одним голосом Windows TTS и выполняет один успешный проход диаризации через настоящий MCP stdio. Проверяет TXT, объединение блоков, отказ от несовместимых форматов до обработки, запрет перезаписи и отсутствие текста/токена в журнале. Тестовые данные удаляются, отчёт метаданных остаётся в игнорируемом `test-results/windows-txt.json`.

В Windows PowerShell из корня репозитория, после установки сервиса:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\windows\validate.ps1 -Repository (Get-Location).ProviderPath
```

Нужны Docker Desktop с GPU, Windows Node.js, русский голос Windows TTS и переменная пользователя Windows `HF_TOKEN` с доступом к модели. Сценарий создаёт временные файлы и использует GPU; он не запускается обычным `npm test`.

Запускатель `install-windows.cmd` ранее проверен в Windows: путь с пробелами, аргументы, коды завершения, видимость ошибки и вызов установщика из UNC-папки WSL.

## Ограничения

- Синтетическая запись с одним голосом не измеряет качество разделения реальной многоголосой встречи.
- Проверка MCP stdio не заменяет проверку каждого приложения агента. После обновления runtime приложение нужно перезапустить.
- Автоматическое присоединение SpeakerUnknown к соседнему участнику не реализовано.
- CI пока отсутствует; результаты локальных тестов не являются результатами GitHub Actions.
