# Сохранение структуры транскрипта

Это рекомендации для разных форматов, а не требование конвертировать всё в JSON. Навык устанавливается простым копированием всей папки `name-speakers`; другие файлы репозитория не нужны.

## TXT и Markdown

Меняй только обозначение автора реплики. Подтверждённое имя: `Алексей [Speaker2]: ...`. Выведенное из самопредставления: `Мария? [Speaker3]: ...`, со статусом `inferred` в таблице. Кандидат по косвенным признакам не заменяет `SpeakerN`. Сохраняй абзацы, время и исходную метку в скобках. Повторное уточнение обновляет существующее отображаемое имя, не накапливает вложенные подписи.

## JSON

Сначала изучи фактическую схему. Для `transcript.diarized.json` v1 оставь неизменными `schema_version`, `source`, `language`, `speakers`, `turns`, `segments[].id`, `speaker_id`, `start`, `end`, `text`, `words`. Добавь к репликам `speaker_name` и `speaker_name_status` (`confirmed` или `inferred`); для неизвестных и кандидатов используй null либо отсутствие этих полей. Общую таблицу и локальные поправки сохрани в соседнем `.speakers.json`.

Для чужой схемы сохраняй идентификаторы и неизвестные поля. Если добавление полей нарушает строгую схему, оставь JSON без изменений и сохрани назначения в таблице с отдельной читаемой копией; сообщи пользователю выбранное представление. Не выдавай файл сторонней схемы за контракт whisper.

## SRT и VTT

Сохрани номера блоков, границы времени, настройки cue и служебные блоки. Изменяй только существующий префикс говорящего либо имя в теге VTT `<v ...>`. Экранируй специальные символы имени в разметке. Не переписывай текст реплики, даже если в нём встречается SpeakerN.

## Исправления

При открытии ранее уточнённого результата учитывай его таблицу. Указание «в реплике на 00:42 говорит Алексей» создаёт локальное переопределение, а не глобальную замену. Если в это время несколько реплик, уточни нужную. Самопредставление другого человека в том же кластере может означать ошибку диаризации: не переименовывай весь кластер автоматически.

## Проверка на примере

Участники: Саша, Алексей, Мария. `Speaker1` обращается к Алексею, `Speaker2` отвечает «Давайте я начну», `Speaker3` представляется Марией. Без дополнительных оснований Speaker1 остаётся неизвестным, Speaker2 получает только кандидата Алексей, Speaker3 — предположение Мария. После уточнения пользователя «Speaker2 — Алексей» только это соответствие становится подтверждённым. Исходные метки и текст речи сохраняются.
