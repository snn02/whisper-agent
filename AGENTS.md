# Инструкции для агентов

Проект запускает официальный Whisper в одноразовом Docker-контейнере с NVIDIA GPU. Основной сценарий — Windows; WSL поддерживается. MCP использует только модель `small`, начальный язык — `ru`, без перехода на CPU. Не выбирайте другую модель и не запускайте CLI с `--model` без явного указания пользователя. Не записывайте текст распознавания в журнал или ответ MCP; он хранится в файлах результата.

Перед изменениями прочитайте [правила разработки](docs/dev/conventions.md) и затронутые части [README](README.md). Текущие правила использования — в README; результаты и ограничения проверок — в [состоянии проверки](docs/dev/verification.md).

Для нового запроса на распознавание сначала найдите медиа через `list_media`. Путь и формат результата берите из запроса или правил проекта; если их нет, спросите пользователя. Не перезаписывайте результаты без явного разрешения.

Проверяйте затронутый слой один раз после исправления; перед заявлением о готовности нужны свежие результаты тестов. Docker/GPU и Windows-приложения проверяйте в обычной Windows/WSL-сессии: песочница этого проекта возвращает `EPERM` на Docker socket. Не объявляйте эти проверки пройденными по локальным модульным тестам.

Навык назначения имён поставляется отдельно из `skills/name-speakers`, хотя хранится в этом репозитории. Для установки только навыка используйте `scripts/install-skill.mjs` или копирование всей папки навыка; не устанавливайте сервис и его зависимости. Имена участников обрабатывает навык, а не MCP распознавания.

Правило формата: при запросе диаризации используйте `diarize: true` и `output_format: "txt"`. Результат — один TXT с блоками `[м:сс] SpeakerN: текст`, соседние фрагменты одного определённого голоса объединены. Без диаризации формат берите из команды пользователя/правил, при отсутствии спрашивайте. SRT используется только без диаризации. Не запускайте повторное распознавание ради JSON или второго формата к диаризованному TXT.
